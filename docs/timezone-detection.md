# 时区检测与配置

用户指定的 [AYi 原文](https://x.com/AYi_AInotes/status/2106639522586829094) 于 2026-10-11 重新完整阅读。第 2.2、6.1、9 节采用台北，并列出自动时区、定位服务和手机端要求。应用默认按这个目标核对；按 IP 出口和手动选择是用户要求的扩展，结果必须显示所选依据。

| 检测依据       | 目标来源                             | 不完整时的结果                                     |
| -------------- | ------------------------------------ | -------------------------------------------------- |
| 原文建议       | `Asia/Taipei`                        | 系统证据未读取时待确认                             |
| 按当前 IP 出口 | 本次本机出口查询返回的有效 IANA 名称 | 公网未开启、无时区、查询失败、两侧出口不同均待确认 |
| 手动选择       | 用户明确保存的 IANA 名称             | 空值或无效名称不能保存                             |

比较时区名称与别名身份，不能只比较当前 UTC 偏移。`Asia/Shanghai` 与 `Asia/Taipei` 不等价。美国有多个时区，不能从 `US` 推算一个统一目标。当前查询只使用 IPinfo Legacy `/json` 的顶层 `timezone`，不使用 Lite 或 Core 响应；接口差异见 [官方对照](https://support.ipinfo.io/hc/en-us/articles/34121895556242-Legacy-Free-API-vs-IPinfo-Lite)。

IP 数据是所查询出口的时区建议，不证明实际所在地，也不证明 Claude Code 的每一次请求路由。

## 独立证据

- 系统：macOS / Linux 优先读取 `/etc/localtime` 指向的时区，必要时使用只读系统命令；Windows 使用 `Get-TimeZone` 区域 ID。未映射的 Windows ID 保留原值并待确认。
- 进程：读取 CG Claude 当前 Node 进程的 `Intl` 时区，另行核对进程、shell 与 Claude 设置里的 `TZ` 声明。不执行 shell 表达式。
- 浏览器：读取当前应用渲染器时区，同时比较系统和所选目标；其他用于登录 Claude 的浏览器资料需要独立复核。
- 自动时区：macOS 独立读取 `/Library/Preferences/com.apple.timezone.auto Active`。开启提示关注、关闭为通过，未知为待确认，不从当前时区推断。
- 定位服务：单独核对“隐私与安全性 → 定位服务 → 系统服务（详细信息）→ 设定时区”。私有记录不能可靠证明开关状态，因此保留人工复核及设置跳转。
- 手机：单列日期与时间和定位服务两个开关，电脑不能替另一台设备确认。
- 新终端：记录本次配置后复验时间，提供 Node 时区与相关变量名称命令，不打印全部环境秘密。

`Machine.timezone` 在新报告中记录系统值，`runtimeTimezone` 记录进程值。系统取证失败时系统值为未知，报告时间显示按已有 UTC 回退规则处理；不把进程值冒充系统值。

## 配置与历史

`timezoneMode` 是 `article`、`exit`、`manual` 之一。旧偏好没有该字段时，空期望值迁移为原文模式；已有明确期望值迁移为手动模式，以保留用户选择。新设置页和配置向导共用 `TimezonePreferences.vue`。偏好与配置快照一起保存、还原。单独保存检测偏好只改变比较目标；一键配置向导中的系统时区与终端 TZ 节点默认勾选，确认预览后实际修改。

规则版本从 `2026-10-11.8` 升到 `2026-10-11.15`。旧报告继续保留当时的判定与依据，页面提示按新规则复检，不修改既有历史。人工确认记录也不会替代新一轮自动检测的证据。

## 验证

隔离测试覆盖上海误通过、UTC+8 非等价、台北符合、手动目标、旧偏好迁移、IANA 别名、按出口成功和缺失、两侧出口差异、TZ 覆盖、读取失败、复杂声明以及 macOS / Linux / Windows 只读取证。修复与界面验证不修改真实 Claude 配置或系统时区。

## 一键配置与授权

向导预览冻结一个具体目标。原文模式采用 `Asia/Taipei`，手动模式采用用户选择，出口模式先查询有效时区并核对两侧出口；缺少时区或出口不一致时不能执行配置。流程共 13 个节点，系统时区和终端 TZ 可分别取消；每项首次失败后重试 3 次，再失败就跳过。

- macOS：固定 `systemsetup -settimezone` 操作通过 AppleScript 的系统授权窗口请求管理员验证，应用不接收密码。
- Linux：`timedatectl set-timezone` 使用系统 polkit 授权。需要 systemd 与可用的图形授权代理，缺失时如实失败。网络校时保持原设置。
- Windows：已知 IANA 区域映射到 Windows ID，固定 `Set-TimeZone -Id` 通过 UAC 执行，检查退出状态并重新读取。没有映射的时区不能自动配置。
- 终端：保存 `.zshenv`、`.bashrc`、`.profile`，调整已有其他白名单启动文件里的直接 `TZ` 声明，以及 Claude `settings.env.TZ`。不新增 `.bash_profile` 或 `.bash_login`，避免改变 Bash 登录文件优先级。Windows 使用用户 TZ 环境和 Claude 设置。
- 进程：同步本工具的 `ctx.env.TZ` 和生产 Node `process.env.TZ`，隔离模式仅修改模拟状态。其他已运行终端和 Claude Code 会话仍需重开。

复杂 TZ 表达式、条件块、函数、未闭合脚本、自定义 ZDOTDIR 或 Claude 配置目录会阻止相关文件写入。网关、代理、凭据、Hooks 和其他未选择字段保留。所有写入都有原始备份，配置前快照保存可读取的系统时区、进程 TZ、已读取的自动时区开关和 Windows 用户 TZ；还原预览显示这些变更，还原失败会尝试回退且保留还原前快照。旧快照缺少时区记录时，仅恢复其原有范围。

配置后向导请求一个新的浏览器样本，超时标为未检测，不沿用配置前样本，不通过浏览器调试覆盖时区。即使系统和 TZ 节点成功，浏览器仍可能需要重启，报告显示它的真实读数。

实现分工：`server/timezone-settings.ts` 负责平台适配、状态读取与恢复；`server/timezone-config.ts` 负责字段转换；`server/setup-timezone.ts` 连接预览和写入；文件事务继续复用 RepairEngine。新增官方依据列在应用文献页与 [来源审计](reference-audit.md)。授权命令和拒绝路径已用隔离适配器验证；本次不实际更改维护者系统时区，Windows/Linux 图形授权尚未实机验证。

完成页的手动清单复用 `shared/manual-guidance.ts`，覆盖设置路径、终端验证、失败后的复检入口和可选 IPv6 恢复方法。旧复核记录不会隐藏本次任务，任何新人工勾选都不能隐藏 warn / fail 证据。
